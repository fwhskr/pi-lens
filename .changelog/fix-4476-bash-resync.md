- **Language servers see installs, codegen and outside edits before the next check (closes #4476, closes #4507)** — after a bash command rewrote several files the language server already held, pi-lens checked them one at a time, so a dependent could be checked against the old copy of a dependency the same command had rewritten and report a phantom error. The new bytes of every held file a command wrote now reach the language servers first, and a server with measured in-order replies answers one request before the first check to prove it has read them; threaded or unmeasured replies are recorded as undrained; the wait has the edit hook's time budget, and a server that does not answer in time is recorded. A branch switch or reset that rewrites held files gets the same budget, so a slow server no longer misses the move's new bytes. TypeScript 7's native server hands file watching to pi-lens and re-reads a closed file only when told about it by exact path. pi-lens now looks for disk changes at each bash result and each tool call. A dependency install (a lockfile or a package manager's install marker changed) restarts that project's language servers and refuses every diagnostics-cache entry scanned before it. A `.d.ts` file created, edited or deleted by codegen or outside pi, in gitignored directories too, is reported to the live servers by path and refuses the cache entries that could see it. Tool-call looks walk the declaration files at most once every `PI_LENS_DECLARATION_LOOK_MS` milliseconds (default 2000, 0 to walk at every look); a walk over 4096 directories or 2048 declaration files records a degradation instead of passing as clean.
