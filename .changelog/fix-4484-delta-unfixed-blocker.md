- **A second write no longer clears an unfixed blocker (closes #4484)** — When a write left an earlier error in place (it edited another line, or the next turn edited the file again), pi-lens treated "nothing new" as fixed: the write said `✓ clean`, the `--lens-guard` commit gate opened, `lens_diagnostics source=session` and the widget showed no issues, and turn end reported the error as cleared. The error now stays blocking until a check of the file no longer finds it: the write says `🔴 Still unfixed: N blocker(s) reported earlier (L…)` instead of clean, the commit gate stays shut, turn end lists it as unresolved, and the session store and widget keep it. This also holds for linters whose ids are positions (helm-lint), where fixing one error renumbers the next, and for a script run without authorship that leaves the error in place. The error also stays blocking when the write did not touch its lines (tree-sitter and ast-grep check only the edited lines for new blockers), when the language server or linter failed, timed out or did not answer on that write, when a slow checker's re-check was still running, and for an unused declaration that blocked when it was new. A write that removes the error still reports it resolved. A slow checker's re-check that finds the error gone clears it, at the commit gate or at turn end; one that failed clears nothing. A check that skipped the file without reading it no longer reads as clean: a file over a size or line limit, a crashed parser, an unavailable grammar or server. Fixing an error now clears it even when the same rule still matches an untouched line elsewhere. An error that moves with an edit above it keeps its new line number. Once a checker that could not run answers again, it reports an error first written meanwhile. A new error that takes a fixed error's place shows as a new STOP, not as "still unfixed". An error stays blocking after an edit too large to line up with the file's earlier version, after writes to hundreds of other files, and in a file over 2 MiB. After such an edit, a fixed error no longer blocks on an untouched line elsewhere with other text, and an error its checker skipped stays blocking once the file lines up again. A checker that skipped a file with no errors now re-checks only the lines it skipped, so an untouched old finding no longer becomes a new STOP. Turn end lists an error once after a slow checker's re-check settles. An ast-grep error found before the ast-grep language server started stays blocking after an edit elsewhere, when that server does not answer, and when a slow re-check settles, and still clears when fixed. A shellcheck or taplo error stays blocking when the language server that stands in for that linter does not answer.
